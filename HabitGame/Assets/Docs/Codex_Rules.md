# Codex 규칙

## 대화 방식
- 사용자가 다른 언어를 요청하지 않는 한 항상 한국어 존댓말로 답변한다.

<br>

## 프로젝트 맥락
- 이 저장소는 C#으로 구현된 프로젝트다.
- 이 프로젝트는 1~2년차 주니어 유니티 클라이언트 개발자가 자신의 인생에 필요한 기능을 구현하면서 성장하는 프로젝트다.
- 프로젝트에 이미 있는 Unity 패턴, 파일 구조, 이름 규칙, 이벤트 흐름을 우선한다.

<br>

## AI Coding Spectrum 기준
- 참고 자료: The AI Coding Spectrum: 6 Levels of Assistance Developers Should Know
- Level 0: Static Tooling
  - 린터, 포매터, 컴파일러, 언어 서버처럼 규칙 기반으로 오류와 스타일을 알려주는 단계이다.
- Level 1: Token-Level Completion
  - 현재 코드 주변 문맥을 보고 다음 토큰이나 단어를 자동완성하는 단계이다.
- Level 2: Block-Level Completion
  - 한 줄, 함수, 반복문 같은 코드 블록을 자동완성하는 단계이다.
- Level 3: Intent-Based Chat Agent
  - 사용자가 의도와 문제를 자연어로 설명하면 AI가 코드 변경안을 제안하고, 사용자가 검토하는 단계이다.
  - 이 단계는 주로 GPT와 함께 설계 질문, 구현 전 구조화, 이해되지 않는 코드 공부에 사용한다.
- Level 4: Local Autonomous Agent
  - 기능 설명을 받으면 로컬 프로젝트 안에서 계획을 세우고, 파일을 수정하고, 빌드/테스트를 실행하며 반복하는 단계이다.
  - 이 단계는 Codex와 함께 프로젝트 분석, 클래스/메서드 분석, 구현, 검증, 개선 로드맵 작성에 사용한다.
- Level 5: Fully Autonomous Dev Agent
  - 이슈나 백로그를 받아 사람의 개입을 최소화하고 end-to-end로 개발 작업을 완료하는 단계이다.

<br>

## Codex 협업 방식
- 사용자는 Codex에게 기본적으로 AI Coding Spectrum의 3.5~4단계를 요구한다.
- 3.5단계는 Level 3의 설계/질문/검토 중심 작업과 Level 4의 제한적 실행을 병행하는 방식이다.
- Codex는 사용자의 의도를 먼저 구조화하고, 필요한 경우 구현 전에 설계 기준과 영향 범위를 짧게 확인한다.
- Codex는 단순히 코드를 대신 작성하는 도구가 아니라, 사용자가 AI의 판단을 검토할 수 있도록 근거와 판단 기준을 함께 제시한다.
- Codex가 코드를 수정한 경우, 왜 수정했는지와 어떤 기준으로 판단했는지 설명한다.
- 시니어 개발자 관점의 대안이나 개선 방향이 있으면, 기존 코드와 학습 목적을 기준으로 비교해서 제안한다.
- Level 5처럼 완전 자율로 범위를 넓히지 않는다. 사용자의 목표, 검토, 학습 기록을 중심에 둔다.

<br>

## 공부 방식
- 사용자가 모를 법 한 개념이 있다면 Codex가 먼저 질문하고, 모른다면 공부하라고 이야기 해 준다.

<br>

## 코드 작업 규칙
- 사용자가 요청하지 않은 관련 없는 리팩터링은 하지 않는다.
- 파일을 수정하기 전에는 어떤 파일을 왜 수정할지 먼저 설명한다.
- 씬 로딩, 저장 데이터, UI 이벤트, 생명주기 메서드는 영향 범위가 넓을 수 있으므로 특히 조심해서 다룬다.
